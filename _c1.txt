// --- PERMANENT GOOGLE DRIVE ACCESS (refresh tokens) ---
// A pure client-side OAuth token client (GIS) CANNOT obtain a refresh token,
// and a refresh token only ever lives on a server. Two deployment modes:
//
//   A) SHARED "Lab Workspace" MODE (recommended for the lab â€” server/ folder):
//      a tiny token server holds ONE permanent refresh token (the workspace
//      owner's) and mints short-lived access tokens for EVERY browser that
//      opens the app. No scientist ever connects their OWN Google Drive â€” the
//      shared Drive folder is always reachable. This only replaces the Drive
//      step: the app login and every permission stay exactly as configured
//      (scientists still sign in with their name + password; operators and
//      access settings are loaded from the shared Firestore appConfig for all
//      browsers, with or without a Google sign-in). Activate it by:
//        1. deploying server/token-server.js (zero-dependency Node server),
//        2. pasting its HTTPS URL into GOOGLE_TOKEN_EXCHANGE_URL below
//           (keep GOOGLE_DRIVE_SHARED_MODE = true),
//        3. the owner opens the app once with  "?drive-bootstrap=1"  and
//           clicks "Connect Drive" â€” the server stores the credential.
//      Server requests used by the app:
//         POST { grant_type: 'workspace' }           â†’ { access_token, expires_in }
//         POST { code, grant_type: 'authorization_code',
//                access_type: 'offline', prompt: 'consent' }   (owner bootstrap)
//
//   B) No endpoint (empty URL): GIS silent renewal while the user stays
//      logged into Google in this browser; on failure the user reconnects once.
//
// When this is empty the app keeps today's behaviour (no shared server).
